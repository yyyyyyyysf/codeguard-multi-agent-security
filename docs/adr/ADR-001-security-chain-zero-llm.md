# ADR-001: 安全链路零 LLM（Security Chain Zero-LLM）

> **状态**: 已接受（2026-08-03）
> **关联**: PROJECT_RULES.md §16.2, docs/specs/codeguard-v0.1-design-spec.md

## 问题背景

CodeGuard 的核心价值是"在 PR 提交时自动阻断安全风险"。安全结论一旦出错，后果是**放行真实漏洞**或**误伤正常合并**——两者都是产品不可接受的。需要决定：安全审计与冲突裁决环节是否允许使用 LLM 生成结论。

## 现状痛点

- 依赖 CVE 扫描需要**结论可溯源**：每条漏洞必须绑定 CVE 编号 + 官方链接 + 修复版本
- 代码风险扫描（Semgrep）需要**规则可解释**：命中必须对应规则 ID 和代码行号
- 审计日志需满足等保 2.0 / 金融合规的**防篡改 + 可复核**要求
- LLM 存在幻觉风险，且输出不稳定，无法作为"裁决依据"的证据链

## 可选方案

| 方案 | 说明 |
|------|------|
| A. 全链路 LLM 判断 | 安全审计/裁决都由大模型生成结论 |
| B. 全链路纯规则 | 所有环节不用 LLM，纯确定性规则 + 权威漏洞库 |
| C. **混合（最终选择）** | 安全链路（审计+裁决）零 LLM；迁移评估用 LLM 做辅助影响分析 |

## 方案对比

| 维度 | A 全 LLM | B 全规则 | C 混合 |
|------|---------|---------|--------|
| 结论可追溯 | ✗ 无法绑定权威来源 | ✓ 天然可追溯 | ✓ |
| 幻觉风险 | 高 | 无 | 安全域无 / 分析域可接受 |
| 合规（等保 2.0） | ✗ 不满足 | ✓ | ✓ |
| 分析深度（升级影响） | ✓ | ✗ 只能靠静态规则 | ✓ LLM 辅助 |
| 误报/漏报可控性 | 差 | 好 | 好 |

## 最终决策

**采用方案 C：安全主链路（安全审计 → 冲突消解）零 LLM，LLM 仅在迁移评估中做辅助。**

判断依据（三条红线，写入 PROJECT_RULES §16）：
1. **结论可追溯性**：安全结论必须绑定 CVE 编号 / Semgrep 规则 ID + 权威来源链接，黑盒模型做不到
2. **幻觉容忍度**：安全裁决零容忍，LLM 一句错误结论就可能放行漏洞
3. **合规责任**：等保 2.0 要求审计日志 append-only + 链式哈希，AI 结论无法满足

LLM 使用边界：仅 `src/agents/migration/llm_analyzer.py`，且带 Prompt 约束 + JSON 输出校验 + `source` 标记三层防护（PROJECT_RULES §4.5）。

## 落地影响

- 安全结论 100% 可复现、可溯源（`rule_set_version` / `cve_db_version` 记录）
- 迁移评估获得"代码影响分析"能力，且不影响安全裁决（双链路隔离）
- 合规叙事：安全结论不依赖黑盒模型，是产品可对客户承诺的合规卖点

## 实施步骤

1. 安全审计 Agent：CVE 三级缓存扫描 + Semgrep 规则扫描（零 LLM）✅
2. 冲突消解 Agent：自动裁决引擎（豁免规则匹配）+ 人在回路（零 LLM）✅
3. 迁移评估 Agent：AST 规则 + LLM 辅助（受约束）✅

## 遗留问题

- LLM 辅助结论为"参考性"，报告需标注来源，防止被误当裁决依据
- 后续若引入 LLM 解读层，必须保持"解读 ≠ 裁决"，不触碰安全结论
